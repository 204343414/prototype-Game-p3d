下列 Phase 编号是能力分层，不再是必须顺序执行的旧排期；部署版本与本轮证据范围见 `HANDOFF.md`。

## 1. 北极星目标与边界

将《Prototype》(2009) 的角色、骨骼动画、曼哈顿静态地图及音效，以**本地、可复现、可审计**的研究工作流整理出来，最终用于一个私人的 VRChat 游戏考古展览/纪念馆。

### 成功的最终体验

- 用户可在本地的“角色选择/道具栏”中浏览已纳入范围的角色；点击角色可看其网格、贴图、骨架与可用动作。
- 每个已纳入范围的角色都有可追溯的来源条目、骨架、动作清单、解析状态和预览状态；不靠文件名猜测、不靠口头记忆。
- 动作在预览器中按正确骨架、合理位移和正确帧率播放；可区分循环/非循环。
- 地图可按 Cell 浏览、检查材质和接缝，并按需加载；城市主体与局部实例/gameplay 图层分开。
- 音效能被清点、检索、试听并与角色/动作/场景建立元数据关联。
- 在展览交互、视觉设计、授权范围和质量标准基本定稿后，再批量产出最终的模型/动画导出物并进行 VRChat 集成。

### 不可违反的边界

- 仓库只提交原创代码、测试、格式文档、合成测试夹具和元数据；**绝不提交**游戏提取的模型、贴图、音频、`.glb`、`.gltf` 或归档文件。
- 使用和产出必须遵守 [`NOTICE.md`](../NOTICE.md)：仅限个人、非商业研究/创作，不公开再分发游戏资源。
- 现有 Alex `.glb` 仅是“解析链路可用”的本地验证产物，**不是**最终 VRChat 资产交付；不要在设计尚未收敛时批量导出全角色。

## 2. 已锁定的起点（不重复排查）

- Alex Mercer 的身体、头、外套、左右手臂共 5 个 Skin 已可合并为全身 T-pose 并正确预览。
- 贴图 DXT 解码必须跳过 `Image_Data` payload 开头 **132 字节 DDS 头**；否则会花屏。
- glTF UV 使用游戏原始 U/V，**不翻转 V 轴，也不交换轴**。这是已经渲染验证的定论；新增角色只做一次肉眼回归检查，不要重开 Alex 的旧问题。
- Alex 有 634 个内嵌动画，混用外部 ZLIB family 与标准/扩展内联 channel，不可一概按其中一种解码。
- ROT-only exporter 与 packed/legacy weight 修复已有真实播放验证，详见 [`animation_format.md` §8](animation_format.md)。进度页记录 11 个动作；本轮未重新播放旧产物。
- 完整动画仍缺 TRAN 标定、内联分支与全角色回归，但不是地图/音效工作的前置阻塞。
- 两端 checkout 与运行中 viewer 需分别核对；保留 dirty 文件，不自动 pull、push 或 self-update。

## 3. 建设原则（“先打地基，后做成品”）

1. **先建立可重复的数据链和测试，再横向堆角色。** 一次性脚本可用于验证，但通用解析层、资产索引和验收机制是后续规模化的地基。
2. **先做一个动画垂直切片，再做全角色覆盖。** Alex 是已验证的模板；让一个动作可靠播放，比同时半解析十个角色更有价值。
3. **事实、推测和设计决策必须分开记录。** 二进制结论要有真实样本/字节级验证；角色归属、动作用途和展陈文案是元数据或设计决策，不能伪装成格式事实。
4. **将原始游戏资产和代码仓库隔离。** 通过本地服务器/受限目录访问游戏文件；报告可记录路径、哈希、尺寸和名称，不复制资产内容。
5. **每一项可见变更都要有真实预览验收。** 贴图、UV、骨架、动画等输出不仅看代码和数值，还须使用现有 headless Chromium 截图或预览器实际检查。
6. **设计可以早期开工，但最终批量导出必须晚于设计收敛。** 早期只生成最少量的本地验证产物；最终命名、LOD、材质策略、动作集合和展览交互确定后再做交付级导出。

## 6. 完成定义（Definition of Done）

本项目不是“能导出一个 Alex 的静态 GLB”就算完成。完成意味着：

- [ ] 工具链在干净环境可复现，代码、文档、测试和资产元数据相互一致。
- [ ] 优先角色池已被真实清点，静态角色和骨骼动画链路不再依赖 Alex 专用假设。
- [ ] 每个纳入首发的角色和动作能在本地预览中正确展示/播放，并有回归证据。
- [ ] 曼哈顿静态场景通过相邻 Cell 的接缝/材质验证，能够按需加载；特殊/动态内容明确分层。
- [ ] 音效被合法地发现、分类、试听和关联，但从不随仓库分发。
- [ ] VRChat 展览体验、性能预算和首发范围在批量最终导出前已定稿。
- [ ] 所有受版权保护的原始及导出资产都留在用户的私有本地环境，Git 仓库只保留可重建它们的工具和记录。
