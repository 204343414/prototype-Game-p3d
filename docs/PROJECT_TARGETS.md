# 项目目标清单与建设顺序

> **用途**：这是项目级的目标、优先级、阶段门槛与验收清单；它回答“接下来建设什么、什么暂时不做”。
>
> **技术现状、格式结论与已知坑**以仓库根目录 [`HANDOFF.md`](../HANDOFF.md) 为准；二进制格式细节以 [`vertex_format.md`](./vertex_format.md) 和 [`animation_format.md`](./animation_format.md) 为准。本文件不重复或推翻已经验证的结论。
>
> **制定日期**：2026-09-14。基于当前 `main` 的归档成果（包含 `2b55a0d` 的文档更新）。

---

## 1. 北极星目标与边界

将《Prototype》(2009) 的角色、骨骼动画及后续音效，以**本地、可复现、可审计**的研究工作流整理出来，最终用于一个私人的 VRChat 游戏考古展览/纪念馆。

### 成功的最终体验

- 用户可在本地的“角色选择/道具栏”中浏览已纳入范围的角色；点击角色可看其网格、贴图、骨架与可用动作。
- 每个已纳入范围的角色都有可追溯的来源条目、骨架、动作清单、解析状态和预览状态；不靠文件名猜测、不靠口头记忆。
- 动作在预览器中按正确骨架、合理位移和正确帧率播放；可区分循环/非循环。
- 音效能被清点、检索、试听并与角色/动作/场景建立元数据关联。
- 在展览交互、视觉设计、授权范围和质量标准基本定稿后，再批量产出最终的模型/动画导出物并进行 VRChat 集成。

### 不可违反的边界

- 仓库只提交原创代码、测试、格式文档、合成测试夹具和元数据；**绝不提交**游戏提取的模型、贴图、音频、`.glb`、`.gltf` 或归档文件。
- 使用和产出必须遵守 [`NOTICE.md`](../NOTICE.md)：仅限个人、非商业研究/创作，不公开再分发游戏资源。
- 现有 Alex `.glb` 仅是“解析链路可用”的本地验证产物，**不是**最终 VRChat 资产交付；不要在设计尚未收敛时批量导出全角色。

## 2. 已锁定的起点（不重复排查）

- Alex Mercer 的身体、头、外套、左右手臂共 5 个 Skin 已可合并为全身 T-pose 并正确预览。
- 贴图 DXT 解码必须跳过 `Image_Data` payload 开头 **132 字节 DDS 头**；否则会花屏。
- glTF UV 使用游戏原始 U/V，**不翻转 V 轴，也不交换轴**。这是已经渲染验证的定论；新增角色只做一次肉眼回归检查，不要重开 Alex 的旧问题。
- Alex 有 634 个内嵌动画；`Animation` 帧数据位于外部 `0x02F00000` ZLIB blob，不要把 `netp3dlib` 的内联帧数据假设直接套到 Prototype。
- 当前动画主阻塞项是 `0x00121119` 的 `TRAN` 位移缩放/参考系标定；详见 [`animation_format.md` §6](./animation_format.md#6-尚待验证待办)。
- GitHub 当前权威整合分支为 **`main`**。历史工作分支/交接文字中出现的 `master` 仅按实际远程状态处理，开始新工作前先 `git fetch origin` 并确认目标分支，避免向错误分支提交。

## 3. 建设原则（“先打地基，后做成品”）

1. **先建立可重复的数据链和测试，再横向堆角色。** 一次性脚本可用于验证，但通用解析层、资产索引和验收机制是后续规模化的地基。
2. **先做一个动画垂直切片，再做全角色覆盖。** Alex 是已验证的模板；让一个动作可靠播放，比同时半解析十个角色更有价值。
3. **事实、推测和设计决策必须分开记录。** 二进制结论要有真实样本/字节级验证；角色归属、动作用途和展陈文案是元数据或设计决策，不能伪装成格式事实。
4. **将原始游戏资产和代码仓库隔离。** 通过本地服务器/受限目录访问游戏文件；报告可记录路径、哈希、尺寸和名称，不复制资产内容。
5. **每一项可见变更都要有真实预览验收。** 贴图、UV、骨架、动画等输出不仅看代码和数值，还须使用现有 headless Chromium 截图或预览器实际检查。
6. **设计可以早期开工，但最终批量导出必须晚于设计收敛。** 早期只生成最少量的本地验证产物；最终命名、LOD、材质策略、动作集合和展览交互确定后再做交付级导出。

## 4. 阶段路线与验收清单

阶段按依赖顺序排列；标有“可并行”的设计/调研工作可提前开展，但不应抢占地基和动画垂直切片的工程时间。

### Phase 0 — 项目地基、可复现性与资产台账

**目标**：让任何新会话或贡献者都能得到一致的源码状态、工具入口、数据边界和资产清单。

- [x] 将 `HANDOFF.md`、本目标清单、README 中的当前状态相互链接；移除或醒目标注 README 中已被 Alex 实测结果推翻的旧叙述。
- [ ] 明确开发依赖与版本：Python、`numpy`、`pygltflib`、`Pillow`、`texture2ddecoder`、Playwright/Chromium；提供可重复安装命令或依赖文件。
- [ ] 建立合成夹具和自动化测试结构：chunk 边界、DDS 头跳过、矩阵/四元数转换、动画 blob 偏移计算均能脱离游戏资产运行。
- [ ] 定义稳定的中间表示（IR）与序列化/诊断格式：`AssetEntry`、`Skeleton`、`SkinMesh`、`AnimationClip`、`AudioEntry`；导出器和 viewer 不直接依赖临时 JSON/chunk 下标。
- [x] 建立**资产清点台账**的 metadata-only schema 与生成器：[`asset_inventory_schema.md`](./asset_inventory_schema.md)、`tools/inventory/rcf_inventory.py` 生成 JSON + 人可读 Markdown；真实游戏资产内容不写入仓库。角色、变体、骨架、动作数、音频数、解析/预览状态、备注和源归档哈希作为后续人工验证层逐步补全。
- [ ] 约定每个游戏资产都只记录元数据和哈希，原始/导出二进制继续由 `.gitignore` 排除。

**验收门槛**：干净 clone 可运行全部不依赖游戏资产的测试；新接手者只读 `HANDOFF.md` + 本文件即可知道该从哪个命令、哪个数据契约和哪个台账开始。

### Phase 1 — Alex 动画垂直切片（当前首个功能里程碑）

**目标**：让一个已验证的 Alex 骨骼动作，以正确变换在现有本地预览器中播放。

- [ ] 选定最小样本（建议 `alex_act_block`），将其名称、chunk 位置、骨架和预期行为登记到台账。
- [ ] 实现 `Animation` 容器、group、channel、ZLIB blob 和 `(count, offset)` 定位符的可测试读取器；严格做范围、对齐和相邻 offset 的零容差校验。
- [ ] 标定 `TRAN` 的缩放系数与参考系：以 `Character_Root` 和 bind pose/local matrix 为锚点，保留计算依据、样本和误差，而非只写一个魔法常数。
- [ ] 将压缩 ROT/TRAN 解码进通用 `AnimationClip` IR；四元数输出始终规范化，并明确 Pure3D `(W,X,Y,Z)` 到 glTF `(X,Y,Z,W)` 的转换位置。
- [ ] 在最小 Alex `.glb` 验证产物中写入 glTF animation channels/samplers；缺少 TRAN 的关节保持 bind pose 位移。
- [ ] 给预览页加入播放/暂停、动作选择、循环状态和时间显示；使用 `AnimationMixer` 做真实播放。
- [ ] 用截图/录屏和骨架可视化检查动作：无骨骼爆炸、镜像、持续漂移、尺度异常或明显的父子层级错误。
- [ ] 为 decoder、glTF 时间戳（`frame / frame_rate`）和关键变换增加单测。

**验收门槛**：从源游戏条目到本地预览的整链可重复运行；`alex_act_block` 至少一条动画稳定播放，且位移缩放有可复查的文档和测试。

### Phase 2 — 角色资产普查与通用化

**目标**：不急于交付最终模型，先准确回答“有哪些目标角色、它们在哪、骨架/材质/动画是否可读”。

优先角色池（按用户已给出的展览优先级）：

1. Blackwatch 黑色守望 ×2
2. 海军陆战队 ×2
3. Hunter 猎手
4. Alpha Hunter 大猎手
5. 终极猎手
6. Elizabeth Greene（E 妈）
7. Cross 上校
8. Alex Mercer（模板角色，已完成静态预览）
9. 各类强化感染僵尸

- [ ] 通过 `art.rcf` 的真实 manifest 枚举定位每个角色；不凭猜测文件名定论。
- [ ] 在台账记录每个候选条目的模型部位、Skin 数、贴图格式、骨架名称/关节数、动画数和缺口。
- [ ] 将 Alex 一次性导出逻辑拆为参数化/通用流程；所有角色都先通过小规模、非提交的本地预览验证。
- [ ] 为已发现的顶点格式分支（`memory_imaged=1` 与 `memory_imaged=0`）建立统一 IR；遇到新变体时先保留原始元数据并写测试，再扩展解析器。
- [ ] 对每个新角色执行一次贴图/UV/骨架回归检查；UV 默认保持原样，只有真实渲染反例才开启新的格式调查。
- [ ] 为每个角色标记“已发现 / 可解析 / 静态预览通过 / 动画通过 / 最终导出待定”状态。

**验收门槛**：优先角色池中每个目标至少有可追溯条目和状态；通用管线面对不同骨架/顶点格式时会显式报告差异，不会静默套用 Alex 假设。

### Phase 3 — 全角色动画覆盖

**目标**：把“Alex 有一个会动的样本”扩展为“每个纳入角色的动作可枚举、可解析、可预览”。

- [ ] 对每个可解析角色建立完整动作索引：名称、类型（骨骼/摄像机）、帧率、帧数、循环标记、group/通道数、解码结果和预览结果。
- [ ] 处理不同角色的 channel 组合、缺失关节和骨架命名差异；绝不把 Alex 的 67 关节假设硬编码为全局规则。
- [ ] 先覆盖骨骼 `PTRN` 动画；`CAM` 动画单列研究任务，不阻塞角色动作播放。
- [ ] 提供动作筛选、播放、循环和失败诊断；失败条目必须在台账中留下明确错误原因。
- [ ] 选取每类角色至少一个短动作和一个长/循环动作做自动化/人工回归预览。

**验收门槛**：优先角色池中每个“可解析”角色的动画均可枚举；目标动作能绑定正确骨架播放，未支持的编码有可定位的失败记录而不是伪成功。

### Phase 4 — 音效基础设施

**目标**：建立不分发原始音频、但可研究、检索和在本地展览中关联音效的工作流。

- [ ] 先枚举并识别音频所在归档、条目命名、容器/编码和元数据；将结论写入专门格式文档。
- [ ] 建立音频台账：条目、格式、时长/采样率（可取得时）、类别、角色/动作/场景关联、解码和试听状态。
- [ ] 实现只在用户本地运行的提取/解码/试听路径；原始音频和转换结果不入库。
- [ ] 为展陈使用定义音效分类（角色语音、动作 SFX、环境、UI、音乐）和触发契约；实际选用集合由设计阶段决定。
- [ ] 为常见格式和损坏/未知条目写可重复测试与诊断。

**验收门槛**：至少能从本地合法游戏安装中完成“发现 → 识别 → 试听 → 写入元数据”的闭环，且没有任何游戏音频被提交到 Git。

### Phase 5 — 展览设计收敛（可在 Phase 1–4 并行调研）

**目标**：在最终资产导出前，确定展览真正需要哪些角色、动作、音效、交互和性能预算。

- [ ] 写一页体验设计：入口、角色选择方式、单角色展台、动作播放、音效触发、信息面板、退出路径。
- [ ] 确定首发角色/动作/音效集合与后续扩展集合，避免“全部导出”却没有展陈用途。
- [ ] 制定 VRChat 技术目标：目标平台（PC/Quest）、每场景角色数、三角面/材质/贴图/骨骼/动画预算、加载策略和交互方案。
- [ ] 确定视觉规则：命名、比例/坐标规范、材质替代策略、版权说明、UI 语言和展签格式。
- [ ] 使用占位/本地验证资产做体验原型，收集可读性与性能反馈；不发布受版权保护资源。
- [ ] 标记“设计基本冻结”的范围与变更流程。

**验收门槛**：有一份经确认的展览规格和首发资产清单；所有最终导出项都有明确用途、目标平台和质量门槛。

### Phase 6 — 最终模型/动画导出与 VRChat 集成（最后开展）

**前置条件**：Phase 0–5 的验收完成，尤其是动画链路、角色台账、音效工作流和体验设计已经收敛。

- [ ] 按已冻结的清单批量生成最终导出物；输出命名、版本、源条目哈希与生成命令可追溯。
- [ ] 根据平台预算进行网格、材质、骨架和动画优化；任何优化保留回归预览。
- [ ] 在目标 VRChat/Unity 工作流中验证导入、Humanoid/Generic 设定、动画控制、音效和交互。
- [ ] 做性能、视觉、动作、音效、版权提示和离线可复现性验收。
- [ ] 只保留脚本、配置、文档和可再生成的元数据于仓库；最终游戏衍生资产保持私有本地存储。

**验收门槛**：私有本地展览的首发范围可完整运行，且任何导出都能从合法本地游戏安装按文档重新生成。

## 5. 即刻执行队列（下一会话从这里开始）

1. **先同步并确认工作基线**：`git fetch origin`，以 `origin/main` 为基准；确认 `HANDOFF.md` 与本文件所写结论一致。不要基于过时的 `docs/roadmap.md` 排期。
2. **完成 Phase 0 的最小地基**：创建资产台账 schema、依赖说明和不含游戏资产的测试夹具/测试入口。
3. **启动 Phase 1 的 Alex 动画垂直切片**：以 `alex_act_block` 为唯一样本，先对 `TRAN` 标定建立可复查证据，再写 glTF animation 输出。
4. **每完成一个可验证切片**：先更新格式文档/测试，再更新 `HANDOFF.md` 和台账，最后 commit 到 `main`。

在用户重新提供本地 viewer 隧道 URL 前，不假装拥有真实游戏文件；可以先完成与游戏资源无关的解析接口、夹具和测试。

## 6. 完成定义（Definition of Done）

本项目不是“能导出一个 Alex 的静态 GLB”就算完成。完成意味着：

- [ ] 工具链在干净环境可复现，代码、文档、测试和资产元数据相互一致。
- [ ] 优先角色池已被真实清点，静态角色和骨骼动画链路不再依赖 Alex 专用假设。
- [ ] 每个纳入首发的角色和动作能在本地预览中正确展示/播放，并有回归证据。
- [ ] 音效被合法地发现、分类、试听和关联，但从不随仓库分发。
- [ ] VRChat 展览体验、性能预算和首发范围在批量最终导出前已定稿。
- [ ] 所有受版权保护的原始及导出资产都留在用户的私有本地环境，Git 仓库只保留可重建它们的工具和记录。
